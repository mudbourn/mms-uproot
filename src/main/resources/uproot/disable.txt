# Parts of target mods that cannot be bridged to 26.3 and are switched off instead.
# Format: see disable.Disabler. Names only; nothing from a mod lives in this repo.
# "tentative" in a reason: the rule is a proposal not yet confirmed in a running game.
# Descriptors that mention Minecraft use 26.3 names (the rules run after the remap); * avoids that.

# --- Biomes We've Gone: pumpkin warden (blocks.md R36) ---
# Not disabled any more: its brain is built on 1.21.11 Brain calls, which the stand-ins of shim/entity (LegacyBrainMob, LegacyBrains)
# answer, and the burrow's occupants are the same mob. Its renderer needed the context GeckoLib 5.5's item layer asks for, which a
# ctor rule of renames.txt passes.
# Known limits, with no rule to lift them:
# - The warden's day schedule is the timeline biomeswevegone:pumpkin_warden. No tag in the mod's data lists it (1.21.11 code registered it), so the
#   data converter (ConvertedView.tagTimelines) adds every timeline a pack leaves unlisted to minecraft:timeline/in_overworld; the warden then
#   follows the schedule and shelters in a burrow at rest time.
# - Map marker colour: 26.3's MapDecorationType has no colour and the map_color item component is gone (MapColorComponentRemovalFix
#   deletes it), so the explorer maps keep the vanilla tint. The constructor adapter in renames.txt drops the argument.

# --- CorgiLib (blocks.md section 3.6 and 7) ---
# /placeall runs: its two changed calls are answered by LegacyWorld (see renames.txt).
# The debug sphere and ring helpers (client/RenderUtils) are not disabled: every render call they make exists in 26.3 (the audit lists none
# missing). Nothing in CorgiLib calls them, and nothing has drawn with them on a client yet.
# The scroll hook of the structure box editor (MixinMouseHandler) runs: its target call is Gui.overlay() now (see renames.txt).

# Map decoration tint (R32) needs no rule: the remapper's constructor rule drops the colour argument.

# --- Biomes We've Gone: noise state provider ---
# Its base class now takes a NormalNoise instead of the parameter record and the record went package-private.
# It appears in no BWG data file, only in Java, so nothing loses a feature; a stand-in base class would be a new subsystem.
stub net/potionstudios/biomeswevegone/world/level/levelgen/feature/stateproviders/BetweenNoiseThresholdProvider | noise state provider on an API that was rebuilt; no BWG data uses it
skip legacy_state_provider_type biomeswevegone:between_noise_threshold_provider | its provider class is disabled, so its type is not registered

# --- Biomes We've Gone: surface rules ---
# 26.3 replaced SurfaceRules with material rules; Uproot's shim/surface stands in for the old API and converts what a
# mod builds, so the rule sources and the TerraBlender call run (see renames.txt). What does not carry over is below.
# The mixin on the 1.21.11 surface system does two jobs. It gives the bands rule source the surface system's seeded random and
# secondary noise (the stand-in system of shim/surface has both, and the mixin is applied to it), and it injects the
# eroded-badlands pillars into the surface pass for two biomes. 26.3 has no such pass to inject into (renames.txt marks the
# injector optional), and Uproot's own MaterialSystemMixin restores the pillars.

# --- Biomes We've Gone: client model access (first client run) ---
# The extra block-state models (BlockStateModel baked from a ResolvedModel through SingleVariant) have no 26.3 form.
noop net/potionstudios/biomeswevegone/fabric/client/BiomesWeveGoneClientFabric lambda$blockStateModel$4 * | unreachable: its only user, blockStateModel, is sent to the shim by a callmove in renames.txt, and it builds the removed SimpleModelWrapper
# Sign sprites: 26.3 has no Sheets material tables; sign bodies are ordinary block models, which data.ConvertedAssets rebuilds from the wood's entity sheet.
noop net/potionstudios/biomeswevegone/client/BiomesWeveGoneClient registerWoodTypes * | fills the Sheets sign material tables, which 26.3 does not have
# The wreath draws its block model through SubmitNodeCollector.submitBlockModel with the removed BlockStateModel

# --- Furnish: furniture workbench recipe ---
# The recipe's own serializer class cannot load (RecipeSerializer is a record in 26.3), so the recipe class must not build it; the
# SERIALIZER reads are moved to the record serializer of shim/recipe (renames.txt).
noop io/github/wouink/furnish/recipe/FurnitureRecipe <clinit> * | the recipe class must not build its own serializer; RecipeSerializer is a record in 26.3

# --- owo-lib: copium ore hook ---
# Copenhagen captures the locals of OreFeature.doPlace; 26.3 walks BlockReplacement there where 26.2 walked OreConfiguration.TargetBlockState, so
# the capture is invalid, and a failed local capture is a critical error that require=0 does not soften. The hook only records ore positions for
# blocks a mod registered through owo's Maldenhagen.injectCopium, an opt-in nobody needs; no vanilla or owo behaviour depends on it.
mixin io/wispforest/owo/mixin/Copenhagen | ore-position hook on locals that 26.3 reshaped; opt-in niche feature

# --- owo-lib: blur surface ---
# owo's blur draws through its own uniform ring (net.minecraft.client.renderer.DynamicUniformStorage, which 26.3 replaced by DynamicGpuData) and
# a GLSL shader written for the 26.2 layout (no explicit locations, a different DynamicTransforms order). Porting it would be a renderer of
# Uproot's own. Without it Surface.blur draws nothing, so a blurred panel keeps the plain background behind it; nothing else depends on it.
noop io/wispforest/owo/ui/renderstate/BlurQuadElementRenderState initialize * | blur input target and uniform ring use 26.2's renderer internals
noop io/wispforest/owo/ui/core/Surface lambda$blur$0 * | blur surface draws a quad through the removed uniform ring; the surface paints nothing instead
# The invoker for SetComponentsFunction's constructor is not applied: 26.3's constructor takes a condition holder and is private. Its one caller,
# the lambda of owo's LootOps.injectItemStack, is moved to shim.compat.LegacyLoot.setComponents by a rule of renames-26x.txt.
mixin io/wispforest/owo/mixin/SetComponentsFunctionAccessor | constructor invoker for a constructor that changed shape; its caller is rerouted to a shim
# Recipe remainders: owo reads an "owo:remainders" entry of a recipe JSON as the recipe is parsed, through a call inside
# SimpleJsonResourceReloadListener.scanDirectory and a lister field of RecipeManager that 26.3 no longer has. Only data packs that use
# owo:remainders lose the entry's effect (their recipes still load).
mixin io/wispforest/owo/mixin/extension/SimpleJsonResourceReloadListenerMixin | recipe parsing moved out of scanDirectory
mixin io/wispforest/owo/mixin/extension/recipe/RecipeManagerAccessor | its only reader is the disabled recipe remainders hook
# Accessors for renderer internals (CommandEncoder.backend, GlProgram.uniformsByName) that owo never reads and 26.3's renderer lacks
mixin io/wispforest/owo/mixin/ui/CommandEncoderAccessor | field no longer exists; no owo class reads it
mixin io/wispforest/owo/mixin/shader/GlProgramAccessor | field no longer exists; no owo class reads it
# Braid, owo's second UI toolkit: its extra OS window shares the GL context of the main one (GLFW), and in-world displays draw before the level
# render call, which 26.3 moved. Neither is used by owo's own config screens or by the mods that depend on owo.
mixin io/wispforest/owo/mixin/braid/WindowMixin | secondary Braid windows need GLFW window creation, which 26.3 has not
mixin io/wispforest/owo/mixin/ui/display/GameRendererMixin | Braid displays draw before GameRenderer.render's level call, which no longer exists
# The cube map component renders into a texture the component names, through a render pass call whose clear-colour argument changed type
mixin io/wispforest/owo/mixin/ui/CubeMapMixin | CommandEncoder.createRenderPass changed its arguments
# owo's own link opener for macOS and Linux (Util.OS.openUri(URI)); 26.3 opens links in Blaze3D
mixin io/wispforest/owo/mixin/tweaks/OperatingSystemMixin | Util$OS has no openUri(URI) to overwrite in 26.3
